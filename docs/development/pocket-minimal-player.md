# 最小MDXプレイヤー ループ・リピート切り替えの実機確認（r4）

対象は Firmware 2.6、core `0.16.0-player-r4`、音声インターフェースHYB4です。
r3に、Yで2周・3周・5周・無限を切り替える機能を追加しました。

## インストール

すでにr1〜r3でM3U曲集を使っている場合:

1. `minimal-player-r4-update.zip` をPCで展開します。
2. `Cores`、`Assets`、`Platforms` をSDカードの同名フォルダーへコピーします。
   更新用ZIPには曲集の `playlist.hpl` が入っていないため、取り込んだ曲集が残ります。
3. Pocketで `RPCMP.MinimalPlayer` を開き、`Playlist.json` を選びます。
4. 曲一覧が表示され、Aを押すまでは無音であることを確認します。
   起動時にAを押しっぱなしでも再生は始まりません。一度離して押してください。

最初から導入する場合や、以前の6曲で確認する場合は `minimal-player-r4.zip` を使います。
こちらには6曲の `playlist.hpl` が含まれるため、同じ場所の曲集は置き換わります。
曲名は同梱の `曲目一覧.md` を参照してください。`試聴用` のWAVはPC参照エンジンの
冒頭部分で、Pocket録音ではありません。

FPGAと起動ROM・アプリは、この候補の組み合わせで更新してください。
PCのM3U取り込み方法とHPL1曲集形式は同じです。

## 操作と連続再生

| 操作・状態 | 動作 |
| --- | --- |
| 上下 | 一覧の曲を選択。長押しで連続移動 |
| 左右 | 13曲ずつページ移動。端では止まる |
| A | 選択曲を先頭から再生。以後は現在のループ／リピート設定に従う。再生中も切り替え可能 |
| B | 停止し、自動送りも解除。一覧の選択位置を保持 |
| X | 再生中の曲を一時停止・再開。一覧で別の曲を選んでいても元の曲に作用 |
| Y | 2周→3周→5周→無限→2周。画面上部に現在の設定を表示 |
| 2・3・5周 | ループ曲はイントロ1回＋指定周数の後、FM・PCMとも5秒でフェードして次曲へ。自然に終わる曲は1回で次曲へ。M3U末尾で停止 |
| 無限／1曲リピート | ループ曲はフェードせず継続。自然に終わる曲は先頭から再生し直す。M3U末尾でも同じ曲を繰り返す |
| 曲単位のエラー | その曲を飛ばす。残りがすべてエラーでも末尾で停止 |

一覧を移動するだけでは再生順は変わりません。選択行の背景色と再生中の曲の左端の印は
独立しています。自動で次曲へ進んでも、カーソルと表示ページは動きません。
画面下には再生中の曲名を表示します。次曲の読み込み中は一旦無音になります。
一時停止中は「一時停止中」と表示し、曲・ループ回数・フェード・自動送りを止めます。
一覧は操作できます。Aなら選択曲の先頭から新しく再生し、Bなら停止します。
停止後のXでは再生しません。Xの長押しでは繰り返し切り替えません。
Yも長押しでは繰り返し切り替えません。同時押しはB、A、X、Yの順に優先します。
X/Y割り当ては当面のもので、UI整備後に変更できます。

設定変更は現在の曲から反映し、再生位置と曲開始からの周回数を保ちます。
指定回数をすでに終えていれば、その時点から5秒でフェードします。フェード中に
回数を増やして終了条件を満たさなくなった場合や、無限にした場合は、音量を滑らかに
戻して再生を続けます。変更後も終了条件を満たす場合は、残りのフェードを続けます。
一時停止中にも設定でき、無音のまま保持し、Xで再開すると新しい設定で続けます。
曲の終了処理と切り替えが重なった場合は、終了済みの音を巻き戻さず、その時点の設定で
再演奏・次曲送りを決めます。停止中・「再生終了」表示後にYだけを押しても再生しません。
設定はB停止・A選曲・自動送りでも維持します。通常再起動・電源OFF後は2周に戻り、
勝手には再生しません。シャッフルと設定保存は今回の対象外です。

## 確認してほしいこと

1. 起動時の無音、日本語の曲名、M3U順の一覧、上下・左右の操作を確認します。
2. 停止中にYで2周→3周→5周→無限→2周と表示が変わり、音が出ないことを確認します。
   Y長押しでは1回だけ切り替わることも確認します。
3. ループ部分の分かる曲で2・3・5周をそれぞれ選んでAを押し、指定周数の後に
   約5秒フェードして次曲へ進むことを確認します。FM・PCM両方の音を確認してください。
4. 無限にして、2周を超えても同じ曲がフェードせず続くことを確認します。そのまま
   Yで2周に戻すと、位置を保ったまま約5秒フェードして次曲へ進むことを確認します。
5. 2周設定でフェードが始まったら、Yで3周へ、または無限まで切り替えます。
   終了条件を満たさなくなれば音量が戻り、先頭に戻らず続くことを確認します。
6. Xで一時停止してYで設定を変え、一覧も操作します。無音と元の曲の位置を保ち、
   Xで新設定のまま再開することを確認します。フェード中の一時停止でも試してください。
7. 自然に終わる曲があれば、2・3・5周では1回で次曲へ、無限では先頭から繰り返す
   ことを確認します。M3U末尾でも同じ動作になり、無限以外では停止することを確認します。
8. Aで別の曲へ、Bで停止、停止後Xは無音、Aで先頭から再生を確認します。
   設定は維持され、自動送り時にカーソルとページが動かないことを確認します。
9. 通常再起動・電源OFF後の起動で、無音かつ2周設定に戻ることを確認します。
   再生中の音切れ・ノイズ・位置の飛び・テンポの乱れ・入力遅延があれば記録してください。

エラー送りは自作の異常データを使うホスト試験でも確認します。手元の曲を壊す必要は
ありません。実機でエラーが出た場合は、飛ばして次曲へ進むかを記録してください。
対象の曲や状況がない項目は「対象なし」と記載してください。

停止後の `R / F / D / V / Q` は、最大音声生成・FIFO転送・描画片・画面提示時間
（us）と最小キュー残量（62.5kHzのフレーム数）です。R/F/Qは直近の再生、D/Vは
起動後の最大値です。表示は画面更新時の値です。

`SKIP` は今回の連続再生で飛ばした曲数、`#` は最後に失敗した曲の番号です。
`E1` は曲データの読み込み・検査、`E2` はエンジン、`E3` は音声装置、`E4` は供給待ちや
一時停止・再開・ループ切替の応答待ちのタイムアウトです。Aで新しく再生を始めると、前回のSKIP記録は消えます。
`E5` は音声リセット失敗なので停止します。コアを再起動してください。
起動時の `Playlist load failed` は曲集自体を読めない状態です。コピー内容を確認してください。

## 開発者向けパッケージ生成

検証済みの準備済みMDX/PDXと `tracks.json` を指定します。

```powershell
python -B tools/pocket_hybrid_package.py --shell out/build/repeat-candidate-r4 --cpu out/build/minimal-player-cpu-r4 --firmware out/build/repeat-firmware-r4/src/firmware/os/bld/pocket --tracks out/build/hybrid-real-inputs-r2/prepared/tracks.json --output out/build/minimal-player-r4
```

出力先は未使用の名前を指定します。全体ZIPと曲集を含まない更新用ZIPを生成します。
全体ZIPには私有楽曲を含むため、ローカルでの実機確認用です。
