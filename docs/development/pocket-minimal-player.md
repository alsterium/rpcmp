# 最小MDXプレイヤー 一時停止・再開の実機確認（r3）

対象は Firmware 2.6、core `0.15.0-player-r3`、音声インターフェースHYB3です。
r2の連続再生に、FM・PCM両方の一時停止・再開を追加しました。

## インストール

すでにr1/r2でM3U曲集を使っている場合:

1. `minimal-player-r3-update.zip` をPCで展開します。
2. `Cores`、`Assets`、`Platforms` をSDカードの同名フォルダーへコピーします。
   更新用ZIPには曲集の `playlist.hpl` が入っていないため、取り込んだ曲集が残ります。
3. Pocketで `RPCMP.MinimalPlayer` を開き、`Playlist.json` を選びます。
4. 曲一覧が表示され、Aを押すまでは無音であることを確認します。
   起動時にAを押しっぱなしでも再生は始まりません。一度離して押してください。

最初から導入する場合や、以前の6曲で確認する場合は `minimal-player-r3.zip` を使います。
こちらには6曲の `playlist.hpl` が含まれるため、同じ場所の曲集は置き換わります。
曲名は同梱の `曲目一覧.md` を参照してください。`試聴用` のWAVはPC参照エンジンの
冒頭部分で、Pocket録音ではありません。

FPGAと起動ROM・アプリは、この候補の組み合わせで更新してください。
PCのM3U取り込み方法とHPL1曲集形式は同じです。

## 操作と連続再生

| 操作・状態 | 動作 |
| --- | --- |
| 上下 | 一覧の曲を選択。長押しで連続移動 |
| 左右 | 13曲ずつページ移動。端では止まる |
| A | 選択曲を先頭から再生し、その曲からM3U順に続ける。再生中も切り替え可能 |
| B | 停止し、自動送りも解除。一覧の選択位置を保持 |
| X | 再生中の曲を一時停止・再開。一覧で別の曲を選んでいても元の曲に作用 |
| ループ曲 | イントロ1回＋ループ部分2周の後、FM・PCMとも5秒でフェードして次曲へ |
| 自然に終わる曲 | 1回で次曲へ。最後の曲を終えると停止 |
| 曲単位のエラー | その曲を飛ばす。残りがすべてエラーでも末尾で停止 |

一覧を移動するだけでは再生順は変わりません。選択行の背景色と再生中の曲の左端の印は
独立しています。自動で次曲へ進んでも、カーソルと表示ページは動きません。
画面下には再生中の曲名を表示します。次曲の読み込み中は一旦無音になります。
一時停止中は「一時停止中」と表示し、曲・ループ回数・フェード・自動送りを止めます。
一覧は操作できます。Aなら選択曲の先頭から新しく再生し、Bなら停止します。
停止後のXでは再生しません。Xの長押しでは繰り返し切り替えません。
同時押しはB、A、Xの順に優先します。X割り当ては当面のもので、UI整備後に変更できます。
ループ設定の切り替え・シャッフル・設定保存は今回の対象外です。

## 確認してほしいこと

1. 起動時の無音、日本語の曲名、M3U順の一覧、上下・左右の操作を確認します。
2. FMのみの曲とPCMありの曲で、Aで再生してからXを押します。左右とも無音になり、
   「一時停止中」と表示されることを確認します。10秒ほど待ち、Xで続きから再開します。
3. PCMの曲で約1分一時停止してから再開します。曲が先へ進んだり、最初に戻ったりせず、
   エラー・テンポの乱れ・音切れがないことを確認します。
4. 一時停止中に別の曲・ページへ移動し、Xで元の曲が再開することを確認します。
   再び一時停止し、Aなら選択曲の先頭から再生、Bなら停止になることを確認します。
   Bの後にXを押しても無音のまま、Aなら先頭から再生できることを確認します。
5. フェード途中でXを押し、10秒ほど待って再開します。残りのフェードを続けてから
   M3U順の次曲へ進み、一時停止中には次曲へ進まないことを確認します。
6. Xの長押し・数回の停止/再開、曲末尾付近での操作を試します。FM・PCM・左右の音、
   操作時のプチプチ音や再開位置の飛び、入力遅延があれば状況を記録してください。
7. 通常再生の2周＋5秒フェード、自然終了の曲は1回、M3U末尾で停止、
   自動送り時の一覧位置保持・再生中の印を確認します。
8. 一時停止した状態から通常再起動・電源OFF後の起動を行い、無音の一覧に戻り、
   Aで正常再生できることを確認します。再生位置は保存しません。

エラー送りは自作の異常データを使うホスト試験でも確認します。手元の曲を壊す必要は
ありません。実機でエラーが出た場合は、飛ばして次曲へ進むかを記録してください。
対象の曲や状況がない項目は「対象なし」と記載してください。

停止後の `R / F / D / V / Q` は、最大音声生成・FIFO転送・描画片・画面提示時間
（us）と最小キュー残量（62.5kHzのフレーム数）です。R/F/Qは直近の再生、D/Vは
起動後の最大値です。表示は画面更新時の値です。

`SKIP` は今回の連続再生で飛ばした曲数、`#` は最後に失敗した曲の番号です。
`E1` は曲データの読み込み・検査、`E2` はエンジン、`E3` は音声装置、`E4` は供給待ちや
一時停止・再開の応答待ちのタイムアウトです。Aで新しく再生を始めると、前回のSKIP記録は消えます。
`E5` は音声リセット失敗なので停止します。コアを再起動してください。
起動時の `Playlist load failed` は曲集自体を読めない状態です。コピー内容を確認してください。


## 開発者向けパッケージ生成

検証済みの準備済みMDX/PDXと `tracks.json` を指定します。

```powershell
python -B tools/pocket_hybrid_package.py --shell out/build/pause-candidate-r3 --cpu out/build/minimal-player-cpu-r3 --firmware out/build/pause-firmware-r3/src/firmware/os/bld/pocket --tracks out/build/hybrid-real-inputs-r2/prepared/tracks.json --output out/build/minimal-player-r3
```

出力先は未使用の名前を指定します。全体ZIPと曲集を含まない更新用ZIPを生成します。
全体ZIPには私有楽曲を含むため、ローカルでの実機確認用です。
