# 最小MDXプレイヤー 複数プレイリストの実機確認（r5）

対象は Firmware 2.6、core `0.17.0-player-r5`、音声インターフェースHYB4です。
r4の音声経路に、複数プレイリストの取り込み・一覧・選曲を追加した確認候補です。
最大100リスト×300曲の資源使用量・操作感は、今回の実機確認対象です。

## インストール

まず同梱の確認曲で試す場合:

1. `minimal-player-r5.zip` を展開します。
2. コアを終了し、Cores・Assets・PlatformsをSDの同名フォルダーへコピーします。
3. PocketでRPCMP.MinimalPlayer → Playlist.jsonを開きます。
4. プレイリスト一覧が出て、リストを開いても無音、曲をAで決定すると再生することを確認します。

全体ZIPには以前確認した6曲を使う「01_確認曲」「02_ページ確認」「03_別リスト」が
入っています。「02_ページ確認」は同じ6曲を繰り返して30登録にした操作確認用です。
曲集 `playlist.hpl` は置き換わるため、現在の曲集を残したい場合はコピー前に保管してください。
曲目は同梱の `曲目一覧.md` を参照。試聴用WAVはPC参照エンジンの音声で、Pocket録音ではありません。

自分のM3Uを使う場合は、[取り込み手順](m3u-library.md)に従いHPL2曲集を作り直します。
`minimal-player-r5-update.zip` はアプリ等の更新だけで曲集を含みません。
**r1〜r4のHPL1曲集を残したままではr5は起動時の読み込みエラーになります。**
r5更新用ZIPと、新しく取り込んだ曲集の両方をコピーしてください。
旧候補を試す場合は、保管したr4パッケージとHPL1曲集を一緒に戻してください。

## 操作

| 操作・状態 | 動作 |
| --- | --- |
| 上下 | 一覧の項目を選択。長押しで連続移動 |
| 左右 | ページ移動。リスト一覧は13件、曲一覧は12曲。端では止まる |
| リスト一覧でA | 選んだリストを開く。音楽は開始・切り替えしない |
| 曲の行でA | その曲の先頭から再生し、そのリストを連続再生の対象にする |
| 戻る行でA | 再生を続けてプレイリスト一覧へ戻る |
| B | 停止し、自動送りも解除。画面の階層は変えない |
| X | 再生中の曲を一時停止・再開。別リストを閲覧中でも元の曲に作用 |
| Y | 2周→3周→5周→無限→2周。リストを変えても設定を保持 |

曲一覧の各ページの先頭に「プレイリスト一覧へ」があります。ページの先頭曲から
上を押すと戻る行に移れます。そこでAを押すと一覧へ戻り、下を押すと曲へ戻ります。
リストを開き直すと、戻る行へ移る前の曲・ページに復帰します。電源を切ると記憶は消えます。

閲覧だけでは再生元を変更しません。別リストを開いていても元のリスト順に進みます。
曲をAで決定したときに切り替わります。再生中の印とカーソルは別で、自動送りでは
カーソル・ページを動かしません。上に閲覧中のリスト、下に再生中のリスト・曲名を表示します。

2・3・5周はイントロ1回＋指定周数の後、FM・PCMとも約5秒でフェードして次曲へ。
自然に終わる曲は1回。現在のリスト末尾で停止し、次のリストへは進みません。
無限では同じ曲を続け、自然終了した曲は先頭から繰り返します。
Y変更は現在位置を保って反映し、回数を満たしていればフェードを始めます。
フェード中に終了条件を満たさなくなる設定へ変えた場合は音量を戻して続けます。
一時停止中は無音・位置・フェードを保持します。停止後Xだけでは再生しません。
A/X/Yの長押しは1回だけ作用し、同時押しはB、A、X、Yの順に優先します。
再起動後はリスト一覧・無音・2周設定です。

## 確認してほしいこと

1. 起動と日本語表示を確認します。起動時にAを押したままでも再生せず、リストをAで
   開くだけでも無音であることを確認します。
2. 「01_確認曲」のFM曲またはPCM曲を再生します。戻る行からリスト一覧へ戻り、
   「02_ページ確認」を開いてページ移動します。元の曲の音・テンポが変わらず、
   入力遅延・音切れ・ノイズがないか確認します。
3. 別リストを閲覧したまま元の曲の終了を待ちます。元のリスト内で次曲へ進み、
   閲覧中のカーソル・ページが動かず、下の再生情報が更新されることを確認します。
4. 閲覧中のリストの曲をAで決定し、その曲からそのリスト順に再生することを確認します。
   各リストの最後の曲では停止し、隣のリストに進まないことを確認します。
5. 「02_ページ確認」の2ページ目以降で先頭曲から上→Aで戻り、開き直します。
   先ほどの曲・ページへ戻ることを確認します。別のリストでも位置が独立していることを確認します。
6. Xで一時停止したまま別リストへ移り、Xで元の曲を再開します。一時停止中Aなら選んだ
   新しい曲の先頭から再生し、Bなら停止することを確認します。
7. Yの2→3→5→無限、ループ曲のフェード・自動送り、リスト末尾での無限リピートを
   確認します。閲覧・選曲・停止で設定を保持することを確認します。
8. FM・PCM・左右を聴き、ページ移動を繰り返しながら約1分再生します。
   停止後のR/F/D/V/Q/Iを記録します。
9. 通常再起動・電源OFF後はリスト一覧の先頭、無音・2周設定に戻ることを確認します。

大きい曲集を試す場合は `minimal-player-r5-scale-data.zip` のAssetsをコピーします。
同じ6曲を使った100リスト×300登録で、3万種類の楽曲ではありません。
起動所要時間、最初・中間・最後のリスト／曲への移動と再生を確認し、PCM再生中にも
リスト・ページを往復します。確認後は全体ZIPのAssets、または自分のHPL2曲集を戻せます。

対象の曲や状況がない項目は「対象なし」と記載してください。手元の曲を壊す必要はありません。
実機で曲単位のエラーが出た場合だけ、同じリスト内で飛ばして次曲へ進むかを記録してください。

## 計測値とエラー

R/F/D/Vは最大音声生成・FIFO転送・描画片・画面提示時間（us）、Qは最小キュー残量
（62.5kHzのフレーム数）、Iは起動時の曲集読み込み・検査時間（ms）です。
R/F/Qは直近の再生、D/Vは起動後の最大値、Iは起動時に計測した値です。
画面更新時の値なので、停止後に記録してください。

SKIPは飛ばした曲数、#は最後に失敗した曲の曲集内番号です。
E1は曲データの読み込み・検査、E2はエンジン、E3は音声装置、E4はタイムアウトです。
Aで再生するとSKIP記録は消えます。E5は音声リセット失敗なのでコアを再起動します。
起動時のPlaylist load failedは、HPL1のまま・曲集の破損・読み込み失敗などです。
r5アプリと、新しく取り込んだHPL2曲集が揃っているか確認してください。

## 開発者向けパッケージ生成

準備済みマニフェストは、nameとtracksを持つプレイリストの配列です。
MDX/PDXと参照WAVの相対パスはマニフェストのフォルダー内を指します。

```powershell
python -B tools/pocket_hybrid_package.py --shell out/build/repeat-candidate-r4 --cpu out/build/minimal-player-cpu-r5 --firmware out/build/repeat-firmware-r4/src/firmware/os/bld/pocket --tracks out/build/multiple-playlist-inputs-r5/tracks.json --output out/build/minimal-player-r5
```

FPGA・起動ROM・OSは合格済みr4の組み合わせを再利用します。アプリと曲集はr5で更新します。
出力先は未使用の名前を指定します。全体ZIPと曲集を含まない更新用ZIPを生成します。
全体ZIPと規模確認用データは私有楽曲を含むためローカル確認用です。
