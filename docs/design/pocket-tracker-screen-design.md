# Tracker 風画面の構成と操作案

Status: layout direction accepted, 2026-09-13. ユーザーは
[Issue #1「画面イメージ」](https://github.com/alsterium/rpcmp/issues/1) の画像を当面の
画面構成の基準に指定しました。[詳細仕様](pocket-library-player-spec-draft.md) の Q18〜Q24 を
合わせて反映します。配置・表示方式の決定であり、画像中の全機能の採用や実装完了ではありません。
入力フォーカスの細部は以下の設計案、履歴と保存は
[演奏履歴契約案](pocket-performance-history-contract.md)・
[設定保存契約案](pocket-playback-settings-contract.md) で具体化します。

## 共通フレームと切替対象

| 領域 | 配置と内容 |
| --- | --- |
| ヘッダー | 薄いタイトル帯。演奏データより大きくしない |
| 主表示 | 最も大きい領域。Tracker / チャンネル別鍵盤 / ライブラリを切り替える |
| 下部左 | 曲名・アルバムなどの曲情報 |
| 下部右 | ミニマルな再生・設定アイコンと経過時間・再生状態 |
| 下端 | 現在表示や操作状態の短い表示。装飾を増やして主表示を圧迫しない |

画像の暗い背景、青緑の文字と現在行、細い枠、等幅のデータ列を基準にします。
表示切替では主表示だけを交換し、曲情報と操作パネルの位置は変えません。
最終の論理画面サイズ、フォント、表示行数は Pocket 上の読みやすさと描画予算で固定します。
参照画像の解像度をそのまま実装の framebuffer サイズとしません。
[文字表示profile](pocket-text-rendering-profile.md) は8×16の音名/16進列、16×16の日本語を
初期候補にし、固定glyph集合の容量を確認しています。字体・密度の実機確認はこれからです。

### Tracker

Q23 により、各チャンネルの演奏履歴が行になって縦へ流れる表示です。
８ FM channel を固定列にし、行番号・音高・取得可能な音色などの値を等幅で並べます。
現在行を共通の横帯で示し、上部に channel 名と活動表示を置きます。
画像を参考に、初期案は音名（例 `C-4`）と音色番号の２桁16進数とします。
音高・音色の意味と有効範囲は履歴契約で区別します。表示用の音高数値を MDX opcode と
混同せず、存在しない音色番号や値を作りません。編集機能や未来の pattern 予測は含めません。

描画時点の channel snapshot だけでは、フレーム間に起きた短い音の変化を保存できません。
履歴表示には時刻・世代・連番付きの immutable な共通演奏履歴が必要です。履歴契約案は
schema 2 に最大256件の観測窓を提案します。UI は MDX 内部、
可変 engine state、container offset を読まず、音声に反映された時刻で履歴を扱います。
履歴契約の同時イベント・欠落表示の規則に従い、UI 遅延で音声を待たせません。
履歴を取り逃した場合に偽の行で埋めたり、直前の状態を全イベントの記録と扱ったりしません。

### チャンネル別鍵盤

同じ８ FM channel を縦に並べ、各 channel の鍵盤で現在の発音位置を示します。
key-on / key-off、一時停止、unknown note を区別します。描画のために channel mute や
音源状態を変更しません。履歴表示と同じ演奏状態を別の形で表示します。

### ライブラリ

作品・アルバム一覧から曲一覧へ進む既存の選曲階層を、主表示の中に置きます。
Q22 により、表示を曲一覧へ切り替えても再生を続けられます。カーソル移動だけでは
選曲せず、曲に合わせて A を押したときに PlayTrack を送ります。下部の曲情報は
再生中または停止中の選択曲を示し、単に閲覧している候補の情報で上書きしません。

## 操作の対応と、これまでの決定との整合

| 操作対象・状態 | A | B | L/R |
| --- | --- | --- | --- |
| 再生操作アイコン | Play / Pause / Resume | 停止。停止完了後の次の B で曲一覧へ | 前後曲へ |
| 繰り返し・シャッフルのアイコン | 対象の設定を１回切り替える | 同上 | 前後曲へ |
| 表示切替アイコン | Tracker → 鍵盤 → ライブラリを循環する案 | 同上 | 前後曲へ |
| 曲一覧の曲 | その曲を再生 | 再生中なら停止。停止後はアルバム階層へ戻る案 | 共通操作として前後曲へ切り替える案 |
| アルバム一覧の作品 | 曲一覧へ入る | 再生中なら停止。最上位・停止中は no-op の案 | 同上 |

十字キーは操作対象を移すだけで、A の確定まで再生・設定を変えません。設定アイコンで
A を押しても Pause を重ねて送りません。曲を A で決定した後は直前の Tracker / 鍵盤表示へ
戻り、再生操作アイコンにフォーカスを置く初期案です。初回は Tracker とし、続けて A を
押せば一時停止できる Q16 の操作を保ちます。表示切替アイコンを A で使った場合は
フォーカスをそのアイコンに残し、もう一度 A で次の表示へ進める案です。

Q17 の「Bで停止してから一覧へ戻る」は、再生を止めて戻る経路として残します。
Q22 の表示切替は再生を続けて一覧を見る経路です。この区別により Q17 を撤回する必要は
ありません。自動次曲や snapshot 更新はフォーカスを奪いません。入力表は UI/platform に
置き、後の操作変更で Player / engine / 音声 timing を変えない構造にします。

Q19 の保存対象は曲順・繰り返し・指定回数です。表示中の画面、フォーカス、再生位置まで
永続化する決定ではありません。設定の適用と保存完了は区別します。
Q24 により繰り返しアイコンは A ごとに **2周 → 3周 → 5周 → 無限 → 2周** と切り替えます。
2周は Default、3/5周は Counted、無限は RepeatOne です。シャッフルは別のアイコンで
有効・無効を切り替え、一方の操作が他方の設定を消さないようにします。

## 差し替え可能なフォーカスと入力の初期案

物理入力を `UiAction` にする binding table、フォーカスの隣接表、各 action を command / UI
遷移へ解釈する controller を UI/platform に置きます。renderer は入力を処理せず、Core には
ビュー名・ボタン名・画面座標を渡しません。画面レイアウトを変更しても Player の API は同じです。

操作パネルは、上段 `Previous / PlayPause / Stop / Next`、下段 `View / Repeat / Shuffle` の
２段を初期案にします。未対応・移動先なしの操作も位置を保ち、A で無効理由を短く表示します。
音声制御の未対応を押せる Pause として見せません。無効アイコンもフォーカス可能にして、
snapshot の状態変化で隣接関係が揺れないようにします。

| 現在の focus と方向 | 移動先。command は送らない |
| --- | --- |
| アイコンの左右 | 同じ段の隣。右端は止まる。左端はLibrary表示なら一覧へ、他は止まる |
| 上段から下 | 同じ列の下段。Next の下は Shuffle |
| 下段から上 | 同じ列の上段。Shuffle の上は Stop |
| 上段から上 | Library表示なら一覧へ、それ以外は止まる |
| 下段から下 | その位置に止まる |
| 一覧の上下 | 同じ階層の前後項目。端は止まり、wrapしない |
| 一覧から右 / 左 | 右は PlayPause、左はその位置に止まる |

一覧が空でも一覧領域へ移動でき、右で操作パネルへ戻れます。表示切替アイコンによる
切替は focus を View に残します。Libraryへ入った後は上で Previous、さらに上で一覧へ進めます。
アルバムの A は曲一覧へ進み、一覧に focus を残します。曲の A は、その項目の
library generation / TrackId を使う PlayTrack が accepted になってから直前の
Tracker / 鍵盤表示へ戻り、PlayPause に focus を置きます。拒否なら一覧に留まり理由を示します。
accepted は再生成功の表示ではなく、準備中・失敗は後の snapshot に従います。
accepted 直後からUIにも準備待ちを持ち、古い曲の Playing snapshot によって A を Pause と
誤解釈しません。新しい再生世代の状態を確認してから PlayPause を再び有効にします。

Libraryの閲覧位置は UI 内で世代・AlbumId・TrackIdとともに保持します。曲の ordinal だけを
別の世代に流用しません。初回はアルバム一覧、再度の表示切替では同じ世代の閲覧位置を復元。
Bで再生画面から戻る場合は停止した選択曲の一覧を開きます。選択曲なしならアルバム一覧です。
一覧の取得中は選曲を無効にし、古い generation なら再取得します。自動次曲、L/R、設定保存の
結果は閲覧位置や focus を動かしません。

| B を押した時点 | 動作 |
| --- | --- |
| Playing / Paused / Loading / Ended | Stop を１回送り、現在の表示に留まる |
| Stop が未完了 | Back を予約せず、追加の B は無視。押し続けも追加操作にしない |
| Stopped、Tracker / 鍵盤 | 次の新しい B edge で選択曲の一覧へ。追加の Stop は送らない |
| Stopped / Empty、曲一覧 | 次の新しい B edge でアルバム一覧へ |
| Stopped / Empty、アルバム一覧 | no-op |
| Error | エラーを表示したままにする。復旧可能なら View と一覧から明示的な再選曲が可能 |

Empty の監視表示からの B はアルバム一覧へ移ります。ErrorでBを停止成功と表示したり、
reset failure を Back 操作で消したりしません。復旧不能なら選曲も無効にします。
Stop の accepted 直後に古い Stopped snapshot を見ても、停止完了とみなしません。
要求前より新しい play generation、Stopped、Stopのpending消失を確認し、その後に発生する
B edge だけを戻る操作に使います。画面上の Stop アイコンは常に停止意図で、Backに変えません。

L/R は共通フレームで現在曲の PreviousTrack / NextTrack に対応させる案です。
閲覧中の曲を相対移動の起点にしません。can_previous / can_next が falseなら送信せず理由を
表示します。１回の edge は１要求、長押しでは連続スキップしません。
PlayPause 上の A は Playing→Pause、Paused→Resume、選択ありの Stopped/Ended→Play。
準備中・制御ACK待ち・未選択・Errorでは再生要求を重複送信しません。

通常の d-pad は押下直後に１移動、350 ms保持後は80 msごとに１移動とする初期案です。
時計は入力用の monotonic wall time。処理が遅れたら１回だけ移動し、遅れた repeat をまとめて
再生しません。反対方向同時押しは相殺、縦横同時は縦を優先します。
同じ入力サンプルでは B、L/R、A、d-pad の順に１つだけ action を選びます。L+R は両方とも
発行しません。A/B/L/R は release 後の新 edge が必要で、d-pad の repeat を流用しません。
起動・入力機器再接続時に押されていたボタンは、いったん離すまで新 edge としません。

設定用の A は RepeatStep / ToggleShuffle という意味の入力として、UI 内に最大８件まで
順序を保持する案です。満杯なら新入力を追加せず「操作待ち」と表示します。Core へは先頭の
１件だけを送り、settings.last_policy_result でその command ID の反映結果を確認してから
次を送ります。各送信時に最新の適用済み policy から値を作るため、素早く押しても同じ値を
何度も送ったり、repeat と shuffle が互いを古い値で上書きしたりしません。
この profile の対話的な policy 発行元は一つの UI controller に集約します。
拒否・実行時失敗では当該入力を失敗として表示し、未送信の後続入力は最新 snapshot で解釈します。
通信上の再送は同じ command ID を使います。保存完了は待ちません。
未反映の入力は「変更待ち」として扱い、適用済み・保存済みの表示に混ぜません。

上の時刻・隣接表・待ち上限は技術的な初期案で、Q16 の通り試用後に表の変更で調整できます。
Core / engine / audio の timing は変更しません。

## 参照画像からの調整

| 画像中の要素 | 現在の要件に合わせる扱い |
| --- | --- |
| FM 6列 + PCM / RHY | 初期実装は FM-only の８列。PCM / rhythm の実装をこの画像から追加しない |
| PLAY と PAUSE の別ボタン | 状態に応じた１つの再生／一時停止アイコンに統合する案。A の操作と一致させる |
| 曲長・driver・BPM・速度・音量・spectrum | 取得できる項目のみ表示。速度変更や spectrum 生成は未採用。未知の曲長を推測で埋めない |
| 小さい文字と大量の装飾 | 主表示と日本語曲名の判読性を優先し、実機で密度を確認してから細部を固定 |

ここで音楽データや将来機能の範囲を拡大しません。音色の16進表示などが必要な場合は、
汎用状態へ MDX 固有情報を混ぜず、型付き optional extension の採用を先に検討します。

## 実装前の確認条件

- ３つの主表示を同じ mock / recorded snapshot から描画し、共通パネルが移動しない。
- 再生中に主表示を繰り返し切り替えても、同じ入力からの device event 列・位置が変わらない。
- Tracker の時刻・世代・連番、同時音、短い発音、欠落の扱いを独立した入力から確認する。
- 曲一覧の移動では PlayTrack が出ず、A の確定だけが１回の選曲を起こす。
- 設定アイコンと再生アイコンに対する A が別の command を出し、B / L/R と干渉しない。
- 入力表の差替え、文字の長さ、８ channel の密度、一時停止・Error・未取得値の表示を確認する。

会話内のラフ案は自作ダミーデータによる配置確認です。演奏、保存、履歴取得、Pocket 上の
可読性を検証した実装ではありません。履歴・設定保存の契約案とこの入力表に対し、速い連打、
Stop ACK前後、表示切替、欠落を含む独立した mock trace を実装時に検証します。
文字表示と [保存・音声adapter案](pocket-player-platform-adapters.md) の採用条件を確認し、
M5 の残 gate を明記して実装 milestone を採用します。
