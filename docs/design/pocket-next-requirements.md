# 選曲と基本再生操作の要件

Status: basic requirements accepted, 2026-09-13. Q1〜Q8 のユーザー回答を確定事項
として記録します。詳細設計・公開契約の拡張案・実装は次の作業です。

## 目的と合意した範囲

Pocket 上で100〜300曲の FM-only ライブラリから曲を選び、再生操作できる
プレイヤーを作ります。PC 側はフォルダーから `.rpcmlib` を自動生成します。
１曲再生までの実機結果は [M5](../milestones/M5-real-mdx-library-playback.md) を
参照します。この要件の合意は、新機能の動作確認や M5 完了を意味しません。

| 質問 | ユーザーが選んだ要件 |
| --- | --- |
| Q1 機能優先順位 | 選曲と基本操作：再生・一時停止・再開・停止 |
| Q2 利用規模 | １ライブラリ100〜300曲 |
| Q3 曲の決定 | 決定した曲を再生する。再生中ならその曲へ切り替える |
| Q4 探し方 | 作品・アルバムを選び、その中の曲を選ぶ |
| Q5 曲終了後 | 通常は同じ作品・アルバムの次曲へ進み、最後の曲で停止 |
| Q6 終端のないループ曲 | 通常は２周してフェードアウトし、Q5 の動作へ進む |
| Q7 シャッフル範囲 | ライブラリの全曲 |
| Q8 PC での取り込み | フォルダー単位で自動作成。フォルダー名を作品・アルバム名にし、ファイル名の番号順に曲を並べる |

Q5 の自由回答では、１曲を無期限にループする設定、回数指定のループ、
シャッフルも明示的に要求されました。その後の「同じアルバムの次曲、最後で停止」は
通常再生の既定動作として扱い、これらのモードを削除しません。Q6 の再回答も
「通常は２周、１曲ループや回数指定を選んだ場合はその設定を優先」と一致します。

PDX/PCM、シーク、プレイリスト編集、詳細ビジュアライザーは今回の基本範囲には
含めません。PCM の将来対応は引き続き必要です。シャッフルは今回の範囲に含めます。

## 利用者から見える動作

### 取り込みと選曲

- PC 上でフォルダーごとに作品・アルバムを作成し、１つの `.rpcmlib` にまとめます。
  ファイル名の数値を比較し、例えば `1.mdx`、`2.mdx`、`10.mdx` の順にします。
  数値のない名前、同じ番号、入れ子フォルダー、同名アルバムの規則は詳細設計で固定します。
- Pocket では作品・アルバム一覧から曲一覧へ進みます。カーソル移動だけでは
  再生を変えず、曲を決定すると準備・検証を行い、成功後にその曲を再生します。
  追加の再生ボタン操作は要求しません。
- 再生中の別曲への切り替えは、旧曲を停止・消音してから新曲を準備します。
  準備に失敗した曲を再生中と表示せず、旧曲の投入済みイベントも再発音させません。
- 選択曲、作品・アルバム、再生状態、経過時間、再生モードとエラーを表示します。
  不明な曲長をゼロや確定した時間として表示しません。

### 再生操作と曲の進み方

一時停止中は無音で再生位置を進めず、再開はその位置から続けます。停止は選択曲を
保持して位置を先頭へ戻し、その後の再生は先頭から開始します。停止・曲変更は
ループ中やフェード中も受け付けます。

繰り返し方と次曲の選び方を分けて扱います。通常の曲順はアルバム内の番号順、
シャッフルの対象はライブラリ全曲です。

| 再生設定 | 現在の曲をいつ終了するか | 終了後の動作 |
| --- | --- | --- |
| 通常 | 自然終了する曲はその終端。終端のないループ曲は２周後にフェードアウト | 同じ作品・アルバムの次曲を再生し、最後なら停止 |
| １曲ループ | 停止や設定変更まで同じ曲を無期限に繰り返す | 自動では次曲へ進まない |
| 回数指定 | 指定した回数で繰り返しを終える | 選択中の曲順に従って次曲を選ぶ |
| シャッフル | 選択中の繰り返し設定に従う。既定のループ曲は２周後にフェードアウト | アルバムをまたぎ、ライブラリ全曲から次曲を選ぶ |

シャッフルと１曲ループを併用しても、１曲ループ中は自動選曲しません。
回数指定の数え方、有限曲を繰り返す場合の扱い、フェードの長さ・曲線、
シャッフルの重複規則と全曲を再生し終えた後の扱いは詳細設計で具体化します。

## 既存契約との接続

- [PlayerCommand v1](../../specs/player-command-api.md) の `LoadTrack` 自体は
  暗黙に再生しません。今回の「決定したら再生」は、ロード完了後に再生する意図を
  順序付けて扱う設計にします。受付成功だけでロード完了と見なしたり、途中の別の
  選曲に古い再生要求を適用したりしません。既存コマンドを組み合わせるか、新しい
  コマンドを提案するかは次の仕様設計で決めます。
- v1 にはループ・シャッフル設定コマンドがありません。設定は Core の再生方針と
  して所有し、`PlayerCommand` と [UI State v1](../../specs/ui-state-api.md) の
  snapshot に必要な意味・型・互換性を実装前に提案します。UI 内の隠れた設定や
  レンダリング周期で自動選曲・ループ終了を実行しません。
- [Container v1](../../specs/rpcmlib-v1.md) は album メタデータと複数曲を表現
  できますが、`TRAK` は TrackId 順です。ファイル名の番号順をコンテナの物理順や
  TrackId の大小から推定しません。作品の識別と曲順を保存・参照する契約を設計し、
  必要な拡張は実装前に仕様化します。予約フィールドの転用や既存 ID 定義の変更を
  黙って行いません。ホストの絶対パスやコンテナ offset は UI に公開しません。
- [M5 Pocket profile](pocket-m5-deferred-playback.md) は１曲・１ blob、各 section
  最大64 records、2 MiB コンテナ／1 MiB total decoded blob の制限です。
  このまま100〜300曲に対応できるとは見なしません。メタデータと曲データの読み込み、
  保持期間、曲・blob・文字列数、総容量の予算を見積もって新 profile を定義します。
  100〜300曲は利用要件であり、任意のサイズの300曲が収まるという保証ではありません。
  PRD の1000曲の論理ライブラリ目標も変更しません。
- [MDX v1](../../specs/mdx-v1.md) のソースは不変です。音楽内の短いリピートと
  曲全体の周回を区別し、複数チャンネルやイントロを含む「２周」の判定を仕様化します。
  フェードをソース MDX の書き換えや未対応 opcode の黙認で実現しません。
- 一時停止・再開とフェードは、モックの状態変更だけでは完成しません。投入済み
  イベント、音源の発音状態、音量、時刻を制御する境界と保証を設計し、再生時刻と
  音声処理を UI から独立させます。必要な音声制御の契約案を実装前に示します。

## 完了条件案

以下を次の実装マイルストーンの受け入れ条件に具体化します。これは新しい試験の
実行結果ではありません。

1. 複数の自作フォルダー fixture から作品名と番号順を再現できる。同じ入力から
   バイト単位で同じライブラリを生成し、破損・未対応入力を成功として扱わない。
2. 自作 fixture の100曲・300曲で、アルバム一覧、曲一覧、ID による選曲を確認する。
   決めた曲数・容量上限、その超過、空の入力、番号の重複などの境界も検証する。
3. 曲の決定で検証後に再生が開始し、カーソル移動では再生が変わらない。
   連続した選曲要求やロード失敗でも別の曲を誤って再生しない。
4. 再生、一時停止、再開、停止、別曲への切り替えを、状態・位置・音源出力で検証する。
   停止・切り替え・失敗後に旧曲が鳴らない。
5. 自然終了と２周後のフェード、アルバム内の次曲、アルバム末尾の停止を確認する。
   １曲無限ループと指定回数が既定の２周に上書きされないことも確認する。
6. シャッフルは全ライブラリを対象にし、アルバム境界で制限しない。乱数源を注入し、
   決定的な試験で曲順・停止条件・モード切り替えを検証する。
7. 遅延・停止した UI でも再生・ループ・フェード・自動選曲の結果が変わらない。
   Core 単独、mock UI 単独と依存方向チェックを維持する。
8. クロスビルドでコード・データ・スタック・バッファ予算を確認する。完成候補で
   選曲、各操作、各モード、左右の再生、通常／電源 OFF 後の起動を実機確認する。
   変更で影響しない過去の配置実験を繰り返さない。

## 次の設計作業

まず100〜300曲のアルバム／曲順データと Pocket メモリ予算を設計します。
続いて再生モード、曲単位の周回判定、フェードと一時停止の制御、最小 UI の
ボタン・表示・エラー復帰を定義し、契約案と実装の順序をまとめます。
Q1〜Q8 を再質問せず、通常の設計判断は既存契約と今回の回答に沿って進めます。
新たな利用者向けの選択が必要になった場合は、具体案を示して Question 形式で確認します。

## 保持する残要件と着手境界

現在のマイルストーンは M5 のままです。調査終了は M5 や本番基盤の合格宣言では
ありません。以下は既存の要件として追跡し、新機能の要件決めを止める理由にはしません。

| 残項目 | 現在の扱い |
| --- | --- |
| APF2 実機確認、過去の成果物の完全な再現 | 未確認を保持。今回の調査は終了し、新しい症状が出たら原因解析する |
| 統合 CDC、外部 I/O 制約、タイミング | M5 acceptance 6 / ADR-0008 の本番移行条件として残す |
| APF lifecycle / heartbeat、再生中を含む故障時の消音 | 既存の試験で未確認の範囲を区別し、本番移行条件として残す |
| 将来の PCM・バッファ・ミキサー・UI の資源余裕 | 次の機能予算と合わせて明示し、現在の fit の空きを予約済みと扱わない |

基本要件は合意済みです。詳細設計と合わせて M5 残項目の実施順序と次のマイルストーンを
明示してから実装します。公開契約や既存の合格条件を黙って緩めません。
