# 次の機能要件案

Status: draft, 2026-09-12. 不具合調査を区切って要件決めへ進む方針は承認済み。
下記の機能優先順位と仕様は提案段階で、実装開始や M5 完了を意味しません。

## 到達点と次の目的

FM-only MDX の１曲ライブラリは、実機で左右の再生・１分再生・通常再起動・
電源 OFF 後の起動が確認済みです。ROM/OS の組み合わせ不整合と APF 故障注入の
不備は特定され、修正が用意されています。APF2 の実機での解消確認は未実施です。
過去の経緯と観測範囲は [M5](../milestones/M5-real-mdx-library-playback.md) を参照します。

次の推奨目標は「Pocket 上で曲を選び、再生操作できるプレイヤー」です。
現在の１曲を自動再生する実機確認用アプリから、日常的な操作ができる形へ進めます。

| 優先候補 | 得られること | 要件決めで必要な判断 |
| --- | --- | --- |
| 選曲と基本操作（推奨） | 複数曲の一覧、選曲、再生、一時停止、停止 | 曲数・容量、操作、切り替え・一時停止の意味 |
| PCM / PDX 対応 | 再生可能な MDX の範囲を拡大 | 初回の対応デバイス、依存ファイル、音声混合の予算 |
| 再生表示 | 曲情報・時間・チャンネル状態を確認 | 最初の画面、情報量、文字・表示更新の予算 |

## 推奨案の利用者向け要件

1. PC で作成した１つの `.rpcmlib` を開き、複数の FM-only 曲を一覧に表示する。
   一覧の移動と実際の選曲を区別し、カーソル移動だけでは再生を変えない。
2. 曲を確定すると、その曲を準備して先頭で停止する。再生操作で再生を開始する。
   再生中に別の曲を確定した場合は、旧曲を停止・消音してから新曲を準備する。
3. 一時停止中は無音で再生位置を進めず、再開すると同じ位置から続ける。
   停止は選択曲を保持して位置を先頭へ戻し、次の再生は先頭から開始する。
4. 選択曲、再生状態、経過時間、操作に必要なエラーを最小限の画面で表示する。
   不明な曲長をゼロや推定した確定値で表示しない。
5. 曲の自然終了時は消音して終了状態を表示する。最初の範囲では自動で次曲へ進まず、
   ループ曲は停止操作まで継続する。

これらは提案であり、承認後に次のマイルストーンへ固定します。PDX/PCM、シーク、
シャッフル、プレイリスト編集、詳細ビジュアライザーは別の要件として扱います。

## 既存契約との接続と実装前に決めること

- [PlayerCommand v1](../../specs/player-command-api.md) の `LoadTrack` は暗黙に
  再生しません。`Play` / `Pause` / `Resume` / `Stop` の既存意味を維持します。
  物理ボタンは Pocket 入力アダプターで割り当てます。
- [UI State v1](../../specs/ui-state-api.md) の immutable snapshot で再生状態を
  表示します。一覧には読み取り専用の論理ライブラリ API を使い、UI に
  コンテナ offset、SDK、エンジン内部を公開しません。
- [Container v1](../../specs/rpcmlib-v1.md) は複数曲を表現できますが、現行
  [M5 Pocket profile](pocket-m5-deferred-playback.md) は１曲・１ blob に制限しています。
  次の profile で曲数、blob 数、文字列数、総容量、メモリ所有権を明示します。
  初回は全体を読み込む方式を候補とし、既存の 2 MiB コンテナ／1 MiB decoded blob
  上限内で必要な曲数が収まるか見積もります。Pocket での1000曲対応は今回の
  小規模 profile の合格条件には含めず、PRD の目標として別途追跡します。
- 実曲の一時停止・再開は、モックの状態遷移だけでは完成しません。投入済みの
  音源イベント、時刻、YM2151 の発音状態をどう停止・復帰するかを設計し、
  無音化と再開位置の保証を決めます。停止を一時停止として代用しません。
- 初回の曲順、表示文字、ボタン割り当て、自然終了からの再生操作、エラーからの
  復帰方法、停止までの時間上限を固定します。新しい公開意味が必要なら実装前に
  仕様案として明示します。

## 完了条件案

- 著作権上問題のない自作３曲 fixture で、複数曲の取り込み・一覧・ID 選択を
  ホスト上で再現できる。上限値と上限超過も検証する。
- 再生、一時停止、再開、停止、別曲の選択、自然終了について状態・位置・
  音源イベントの期待結果を定義し、決定的なホストテストで確認する。
- UI が遅延・停止しても再生イベントが変わらず、Core 単独と mock UI 単独の
  ビルド、および依存方向チェックが通る。
- 曲の切り替えや停止後に旧曲の投入済みイベントが発音しない。失敗時は消音し、
  準備に失敗した曲を再生中と表示しない。
- クロスビルドで実際のコード・データ・スタック・バッファ予算を確認する。
  完成候補の実機確認は、選曲と各操作、左右の再生、通常／電源 OFF 後の起動を
  まとめて行う。変更で影響しない過去の配置実験を繰り返さない。

## 保持する残要件と着手境界

現在のマイルストーンは M5 のままです。調査終了は M5 や本番基盤の合格宣言では
ありません。以下は既存の要件として追跡し、新機能の要件決めを止める理由にはしません。

| 残項目 | 現在の扱い |
| --- | --- |
| APF2 実機確認、過去の成果物の完全な再現 | 未確認を保持。今回の調査は終了し、新しい症状が出たら原因解析する |
| 統合 CDC、外部 I/O 制約、タイミング | M5 acceptance 6 / ADR-0008 の本番移行条件として残す |
| APF lifecycle / heartbeat、再生中を含む故障時の消音 | 既存の試験で未確認の範囲を区別し、本番移行条件として残す |
| 将来の PCM・バッファ・ミキサー・UI の資源余裕 | 次の機能予算と合わせて明示し、現在の fit の空きを予約済みと扱わない |

機能優先順位と完了条件を合意した後、M5 残項目の実施順序と次のマイルストーンを
明示してから実装します。公開契約や既存の合格条件を黙って緩めません。
