# アルバム選曲プレイヤーの詳細仕様案

Status: proposal, 2026-09-13. [基本要件](pocket-next-requirements.md) の Q1〜Q8 と
本書の Q9〜Q16 は確定済みです。追加の上限・データ形式・API は設計案であり、公開 v1 契約や
実装を変更しません。現在の作業はこの仕様案を具体化することです。

## Q9〜Q16 の確定事項

| 質問 | 確定した仕様 | 回答状況 |
| --- | --- | --- |
| Q9 ２周の数え方 | イントロ１回＋ループ区間２回。イントロ10秒＋区間30秒なら70秒後にフェード開始 | ユーザー確定 |
| Q10 フェード時間 | ５秒 | ユーザー確定 |
| Q11 全曲シャッフルの一巡後 | 同じ周内は重複なし。全曲を１回ずつ再生したら停止 | ユーザー確定 |
| Q12 未対応・破損曲の混在 | 取り込めた曲で作成し、除外した曲と理由を一覧表示 | ユーザー確定 |
| Q13 回数指定と有限曲 | 回数指定はループ曲だけに適用。自然に終わる曲は１回で次へ進む | ユーザー確定 |
| Q14 曲名表示 | MDX 内の曲名を優先。読めない・空の場合は拡張子を除いたファイル名を使う | ユーザー確定 |
| Q15 再生中の設定変更 | 現在位置を保ち、今の曲から反映。新しい指定回数に到達済みならフェードを開始 | ユーザー確定 |
| Q16 ボタンと変更容易性 | A で再生後は A で一時停止・再開、B で停止。試用後に操作を簡単に変更できる構造にする | ユーザー確定 |

上の例は開始70秒でフェードを始め、75秒で終了します。Q11 は通常再生の
「アルバム末尾で停止」を変更せず、シャッフル時の動作だけを決めます。
各曲の終了条件は選択中の繰り返し設定を優先し、１曲ループ中は自動で
シャッフルの次曲へ進みません。以降の技術的な上限・データ形式は引き続き提案です。

Q9〜Q16 の回答はすべて揃っています。残る技術的な仕様案を詰める際も、確定した
操作を再質問せず、試用後の変更を許容する構造を維持します。

## PC 取り込みの設計案

入力は利用者が指定した１つのルートフォルダーです。配下を再帰的に走査し、
MDX を直接含む各フォルダーを１作品・アルバムにします。子フォルダーの曲を
親アルバムへ混ぜず、MDX のないフォルダーはアルバムにしません。ルート直下の
MDX はルート名のアルバムに含めます。通常ファイルのみ扱い、リンク経由で
入力ルート外へ走査しません。

アルバム名はフォルダーの末尾名です。正規化した相対フォルダー名を識別用キーに
使い、同名でも別のフォルダーは別アルバムとします。キーから識別子を生成し、
ホストの絶対パスはコンテナや UI に渡しません。同名を見分ける表示方法は UI 設計で
決めます。PC のルートを移動しても同じ相対構成なら同じ識別子にします。

曲順は拡張子を除いたファイル名の natural order とします。ASCII 数字の連続区間を
数値として比較し、`1`、`2`、`10` の順に並べます。長い数字列は桁数と文字列で
比較し、固定幅整数への変換による overflow を起こしません。数値が同じ場合と
番号のない名前は、NFC UTF-8 のバイト順で決定的に整列します。大小文字は区別し、
列挙 API の返す順序や OS の locale に依存しません。アルバム一覧も同じ比較規則で
相対フォルダーキーを並べます。

[ADR-0005](../adr/0005-m1-utility-language-and-normalization.md) に従い、NFC 正規化は
取り込み層の責務です。既存 writer は正規化済み入力を前提にするため、任意の
日本語フォルダー名まで現在対応済みとは見なしません。実装前に変換方法と依存を
記録します。曲名抽出と文字表示の仕様もここに接続します。

表示する曲名は MDX 内のタイトルを優先します。[MDX v1](../../specs/mdx-v1.md) が
保持する元のタイトルバイトを、PC 取り込み層で表示用の UTF-8/NFC に変換します。
文字コードの変換が失敗するか、表示用の文字列が空なら、拡張子を除いたファイル名へ
fallback します。タイトルの変換失敗だけで、構造・演奏の検証を通った曲を除外しません。
元の MDX バイトと、ファイル名に基づく曲順は変更しません。具体的な文字コード変換、
制御文字・複数行・文字数制限・対応 glyph は表示仕様で固定します。

各 MDX は既存の FM-only admission を通してから登録し、元の音楽バイトは変更
しません。検出した未対応・破損 MDX と、MDX でない対象外ファイルを区別します。
Q12 に従い、検証を通った曲だけでライブラリを作成し、除外した各曲と理由を PC に
一覧表示します。元の入力順に依存しない並びで取り込み件数・除外件数も報告します。
報告に含む利用者のファイル名や曲名はローカル成果物とし、リポジトリに記録しません。

新しい一括取り込み API は「全件取り込み」「除外ありで作成」「作成失敗」を区別する
案です。除外を全件成功と扱わず、成功した曲が０件なら空のライブラリを出力しません。
サイズ上限超過、writer の整合性エラー、出力書き込み失敗などの全体エラーは、
曲の除外へ付け替えて成功にしません。未完了の出力を完成品として公開せず、既存の
出力がある場合の上書き方法と終了コードを一括取り込みの契約に明記します。
重複 TrackId は現行 writer のエラーを維持し、曲を黙って削除することで処理しません。

この方針は次の一括取り込み profile に対する Q12 の決定です。M5 の一曲取り込みは、
その曲が未対応・破損なら出力しない既存の合格条件と API を維持します。

## アルバムと曲順のデータ契約案

[Container v1](../../specs/rpcmlib-v1.md) の `TRAK` は TrackId 順のままにし、
アルバムの曲順を別の `ALBM` section に持つ案です。既存 TrackId / BlobId /
StringId の生成規則、必須６ section のレイアウト、予約フィールドは維持します。

| 論理レコード | フィールド案 |
| --- | --- |
| Album | 非ゼロの `AlbumId: u64`、名前の `StringId: u64`、表示順 `u32`、曲数 `u32` |
| AlbumTrack | `AlbumId: u64`、アルバム内順序 `u32`、`TrackId: u64` |

アルバム名は既存 `STRS` を参照し、各曲の album メタデータと一致させます。
最初の profile では１曲が１アルバムに属し、全 TrackId がちょうど１回現れます。
アルバム内順序とアルバム表示順は０始まりで連続させます。参照の欠落、重複、
順序の穴、件数不一致はカタログを公開する前に拒否します。アルバム識別子の
ハッシュ入力、衝突処理、保存レコード幅・整列・version は `specs/` 化前に固定します。

`ALBM` は v1 envelope 上では optional section とする案です。既存 reader は
チェックサム検証後に未知 section を無視でき、新しいプレイヤーの profile は
この section の存在と論理検証を追加で要求します。既存一曲の M5 profile は
変更せず、新プレイヤー向けライブラリは PC utility で生成します。optional である
ことを理由に、新プレイヤーでカタログ不正を無視しません。

UI には immutable な `AlbumSummary` / `TrackSummary` のページを返します。
１ページ最大16件、ライブラリ世代番号と論理 ID を付け、選択状態やポインターを
実行中 Core と共有しません。読み取り専用カタログ問い合わせは PlayerCommand と
分け、UI が container offset を扱わないようにします。

## Pocket profile の容量案

最初の実装はコンテナ全体を起動時に一度読み込み、検証後は不変のまま保持します。
曲の選択時に既存 session で選択 MDX 全体を準備し、再生中の storage I/O は行いません。
同時に鳴らす曲は１曲で、クロスフェードや次曲の先行再生は含めません。

| 項目 | 提案する上限 |
| --- | --- |
| 曲 / アルバム / 一意の MDX blob | 各300 |
| コンテナ全体 | 32 MiB、未圧縮 codec 0 のみ |
| MDX １曲 | 既存 MDX v1 と同じ1 MiB |
| decoded blob 合計 | 32 MiB。メタデータ込みでコンテナ上限にも従う |
| section | 16 |
| 汎用 section record 上限 | 4096。曲・blob・album には上記の個別制限も適用 |
| UTF-8 文字列 | 4096件、各4096 bytes以下、文字列本体合計1 MiB以下 |
| カタログ・snapshot・ページ用作業域 | 1 MiBの予算 |
| SD 転送単位 | 既存の4096 bytes以下を維持 |

１曲だけのライブラリも許可します。100〜300曲は対象の利用規模であり、最小100曲を
要求しません。PC 側で曲数と総バイト数を検査し、上限超過時は必要サイズを表示して
出力を拒否します。300曲×1 MiBが必ず収まるとは約束しません。読み込み所要時間は
容量だけから推定せず、実装後に最大サイズを測定します。

### 予算の根拠と測定の境界

[配置レビュー](pocket-m5-placement-review.md) の既存実曲アプリは static が
3,064,632 bytes、そのうちコンテナ領域が2,097,152 bytesです。アプリの static / heap
領域は `0x10400000..0x13a00000` の56,623,104 bytesです。

32 MiBへの置き換えだけを仮定した静的使用量は
`3,064,632 - 2,097,152 + 33,554,432 = 34,521,912 bytes`、残りは22,101,192 bytesです。
追加予算をカタログ1 MiB、UI の文字・描画用作業域2 MiB、再生制御・コード増分1 MiB
とすると、残りは17,906,888 bytesになります。これは既存 map からの計算であり、
新しい ELF の計測値や将来 PCM が収まる証明ではありません。

既存512 KiBの app stack は上記 static / heap 領域の外側です。OS の framebuffer、
audio ring、file cache、OS stack と cached / uncached alias を追加 RAM として
数えません。新しい全 buffer を zero-backed storage として予算化し、実装時の
ELF/map、initialized data、stack、OS 予約域との非重複でこの見積もりを検証します。

## 再生制御の契約案

`LoadTrack` の暗黙に再生しない意味は維持し、選曲と再生を１つの意図として
`PlayTrack(TrackId)` を追加する案です。新しい意図はロード結果と紐付け、
後から届いた選曲や停止で失効したロード結果から再生を開始しません。

`SetPlaybackPolicy` の案は曲順 `AlbumOrder | ShuffleLibrary` と繰り返し方
`Default | RepeatOne | Counted` を独立に指定し、Counted のときだけ正の回数を
必須にします。無期限を巨大な回数や０で表現しません。コマンドの version /
capability と snapshot への公開方法を仕様化し、未対応なら明示的に拒否します。

Q13 により、Counted の回数はループ区間にだけ適用します。例えば Counted=3 なら、
ループ曲はイントロ１回＋ループ区間３回の後に５秒でフェードし、有限曲は終端まで
１回だけ演奏して次曲へ進みます。有限曲を先頭から３回やり直しません。RepeatOne は
別の設定なので、有限曲も終端から先頭へ戻して繰り返します。Default / Counted で
有限曲の自然終端を迎えたときは、無音のフェード待ちを加えず次曲の準備へ進みます。

Q15 により、曲順・繰り返し設定は現在位置を保って今の曲から反映します。
新たな Counted の回数に既に到達している場合は、その時点で５秒のフェードを開始します。
曲順だけの変更は再生中の曲を切り替えず、次の選曲に反映します。フェード中や
一時停止中の再設定、シャッフル履歴の更新方法は状態遷移の仕様で具体化します。

自動送り・シャッフル・フェードを Player の時刻と状態で進め、描画や入力 polling を
時刻の基準にしません。`Pause` は位置を保持して消音し、`Stop` は選択を保持して
先頭に戻します。MDX 内の短い repeat と曲全体の周回は区別し、複数の FM channel の
周回判定、フェードの時刻・利得、投入済み queue と音源状態の停止／復帰については
音声制御仕様を別途詰めます。音源状態を reset して位置だけ保持したものを、
検証せずに正しい一時停止・再開と扱いません。

## 変更しやすい入力・画面操作の設計案

Q16 の A/B の意味を以下の初期フローで実現する案です。曲一覧の A による選曲と、
再生後の A による一時停止を、画面の文脈で区別します。

| 文脈 | A | B |
| --- | --- | --- |
| 曲一覧で曲を選択 | その曲の PlayTrack を送り再生画面へ進む | 再生処理が動作中なら Stop。階層移動とは別の意図にする |
| 再生画面・再生中 | Pause | Stop |
| 再生画面・一時停止中 | Resume | Stop |
| 再生画面・停止中、準備済みの曲あり | Play で先頭から開始 | Stop のまま |
| 再生画面・ロード中 | 再生要求を重複発行しない | 保留中の再生意図を取り消して停止 |

戻る、一覧への移動、L/R の前後曲、長押し・連打などの細部は、画面と入力の
状態遷移表で具体化します。旧質問の B=戻るを全画面共通の確定割り当てとして
残さず、最新の B=停止を基準にします。

構造は `Pocket input -> InputBinding -> UiAction -> UI controller -> PlayerCommand`
とし、一覧移動などの UI 内操作だけは UI controller 内で完結します。物理ボタンと
画面・状態に応じた UiAction の対応を一か所の設定テーブルに集めます。A/B の文字や
PAD の bit は Player・MDX engine・音声処理へ渡しません。

UI controller は意味のある操作を既存または提案する PlayerCommand に変換し、
Core の mutable state を直接変更しません。Core の反映結果は snapshot で読みます。
同じボタンを押し続けたときに Pause/Resume を交互に連発しないよう、押下 edge と
一覧用のリピートを入力層で区別します。ボタン割り当て変更はこの入力テーブルと
対応するホストテストで行い、再生エンジンや音声の timing を変更しません。

試用後に別の割り当てへ差し替え、同じ意味の入力から同じ PlayerCommand 列が出る
ことを mock snapshot で検証できるようにします。物理ボタンの正確な PAD mapping は
Pocket アダプター実装時に確認し、この仕様決定を実機検証と見なしません。

## この仕様案の次の完了条件

Q9〜Q16 は反映済みです。次にカタログの保存形式と公開 API、容量上限、
音声制御を具体化します。[基本要件の完了条件](pocket-next-requirements.md) に加えて、
同じフォルダー構成の再現性、ALBM 不正参照、300/301曲、32 MiB境界、長い番号、
同名フォルダー、古いロード結果、モード組合せの試験を実装前に定義します。
Q12〜Q14 については、正常・未対応・破損の混在、全件除外、全体の書き込み失敗、
有限曲への Counted=3、MDX タイトルの正常・空・変換失敗と曲順の不変を確認します。
再生中の設定変更でも現在位置を保持し、到達済み回数への変更でフェードが始まることを
確認します。
入力については、A の再生／一時停止／再開、B の停止・保留再生取消、押し続けた場合の
重複抑止と、入力割り当てを変更しても同じ意味の command 列になることを確認します。
M5 の残要件と次の実装マイルストーンの順序も明示し、実装にはまだ着手しません。
